# 00 — โจทย์และการตีความ

## สิ่งที่ข้อสอบระบุไว้ตรง ๆ

สร้าง Program ที่มี UI ตามภาพ IT 03-1, IT 03-2, IT 03-3

1. หน้า **IT 03-1** แสดงรายการเอกสาร มี 3 สถานะ: `รออนุมัติ`, `อนุมัติ`, `ไม่อนุมัติ`
2. รายการที่อนุมัติแล้ว **จะไม่สามารถเลือกอนุมัติซ้ำได้**
3. เลือกรายการที่รออนุมัติ กด `อนุมัติ` → แสดง Modal **IT 03-2** กรอกเหตุผล กด `อนุมัติ` เพื่ออัปเดตสถานะ กด `ยกเลิก` เพื่อปิด
4. เลือกรายการที่รออนุมัติ กด `ไม่อนุมัติ` → แสดง Modal **IT 03-3** กรอกเหตุผล กด `ไม่อนุมัติ` เพื่ออัปเดตสถานะ กด `ยกเลิก` เพื่อปิด
5. หมายเหตุ: โครงสร้างฐานข้อมูลออกแบบตามที่เหมาะสม ข้อมูลใส่เป็น mockup

## สิ่งที่ไม่ได้เขียนไว้ แต่อ่านได้จากภาพ

### 1. เป็นการทำงานแบบเลือกหลายรายการ (bulk action)

ปุ่ม `อนุมัติ` / `ไม่อนุมัติ` อยู่ **เหนือตาราง** ไม่ได้อยู่ในแต่ละแถว และทุกแถวมี checkbox
พร้อม checkbox บนหัวตารางสำหรับเลือกทั้งหมด

ลำดับการใช้งานจริงจึงเป็น: ติ๊กหลายแถว → กดปุ่มด้านบนหนึ่งครั้ง → กรอกเหตุผลครั้งเดียว →
อัปเดตทั้งชุด

ผลต่อการออกแบบ: API รับ `documentIds` เป็น array และทำงานใน transaction เดียว

### 2. แถวที่ตัดสินใจแล้ว checkbox เป็นสีเทาและกดไม่ได้

ในภาพ IT 03-1 แถวที่ 2, 3, 5, 6 (อนุมัติ / ไม่อนุมัติ) checkbox เป็นสี่เหลี่ยมเทาทึบ
ต่างจากแถวรออนุมัติที่เป็นกรอบขาว นี่คือหน้าตาของข้อกำหนดข้อ 2

ผลต่อการออกแบบ: บังคับทั้งสองชั้น — UI ปิด checkbox และ Domain โยน exception ถ้ามีคนยิง API ตรง

### 3. คอลัมน์ `เหตุผล` มีค่าทุกแถว รวมแถวที่ยังรออนุมัติ

ภาพแสดง `xxxxx` ในคอลัมน์ `เหตุผล` **ทั้ง 10 แถว** รวมแถวที่สถานะยัง `รออนุมัติ`

แถวที่รออนุมัติยังไม่เคยมีการอนุมัติ ดังนั้นคอลัมน์นี้จะดึงจากประวัติการอนุมัติทั้งหมดไม่ได้
จึงตีความว่าเป็น **เหตุผลที่แนบมากับเอกสารตั้งแต่ยื่น**

ผลต่อการออกแบบ: `documents.reason` มีค่าตั้งแต่ seed ทั้ง 10 แถว และเมื่ออนุมัติ/ไม่อนุมัติ
จะเขียน `approval_log` **และ** ทับ `documents.reason` ด้วยเหตุผลล่าสุด

### 4. ไม่มีคอลัมน์จำนวนเงิน

โครงร่าง schema ตอนแรกมี `Amount (decimal)` กำกับว่าเป็นคอลัมน์ `เหตุผล/xxxxx`
แต่ในภาพไม่มีคอลัมน์ตัวเลขหรือจำนวนเงินเลย คอลัมน์ที่สามคือ `เหตุผล` ซึ่งเป็นข้อความ

ผลต่อการออกแบบ: ตัด `Amount` ออกจากโมเดล ใช้ `Reason nvarchar(500)` แทน

## สิ่งที่อยู่นอกขอบเขต

- **การเข้าสู่ระบบ** ข้อสอบไม่ได้ขอ แต่ `approval_log.created_by` ต้องมีค่า จึงทำ
  `ICurrentUserAccessor` ไว้เป็นจุดต่อ อ่านจาก header `X-User` ถ้าไม่ส่งมาใช้ `demo.user`
- **การสร้าง/แก้ไข/ลบเอกสาร** ข้อสอบขอเฉพาะการอนุมัติ ข้อมูลมาจาก seed
