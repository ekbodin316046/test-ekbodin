# 04 — UI / UX

## แนวทาง

ข้อสอบให้ mockup มาแบบ wireframe หยาบ (หัวเขียว ตารางฟ้า) ซึ่งเป็นการสื่อ *โครงสร้าง*
ไม่ใช่ *ธีมสี* ที่ต้องการจริง จึงยึดสองอย่างพร้อมกัน

1. **พฤติกรรมและโครงตาราง** ทำตาม mockup ทุกจุด (คอลัมน์, ตำแหน่งปุ่ม, checkbox เทา, ข้อความใน modal)
2. **ภาษาการออกแบบ** ใช้ชุดโทนสีและตัวอักษรระดับ production เพื่อให้ดูเป็นระบบงานจริง
   ไม่ใช่หน้า prototype

## เมนูข้าง

เมนูต้องมีของจริงให้กด ไม่ใช่ลิงก์หลอก ทุกหน้าจึงทำงานได้จริงและใช้ข้อมูลชุดเดียวกัน

| เมนู | เส้นทาง | ที่มาของข้อมูล |
|---|---|---|
| อนุมัติเอกสาร (IT 03) | `/it03` | `GET /api/it03/documents` |
| สรุปสถานะเอกสาร | `/summary` | คำนวณจาก endpoint เดิม ไม่เพิ่ม API |
| ข้อมูลสถานะเอกสาร | `/master/status` | `GET /api/it03/statuses` |

หน้าที่กำลังใช้งานได้พื้นหลัง `#6f3088` ผ่าน `routerLinkActive` ของ Angular Router

## กฎการใช้งานที่บังคับในหน้าจอ

- ปุ่ม `อนุมัติ` / `ไม่อนุมัติ` กดไม่ได้ถ้ายังไม่เลือกแถว
- ปุ่มยืนยันใน modal กดไม่ได้จนกรอกเหตุผล (ตัดช่องว่างหัวท้ายก่อนตรวจ)
- แถวที่ไม่ใช่ `รออนุมัติ` เลือกไม่ได้
- ระหว่างบันทึกปุ่มเปลี่ยนเป็น `กำลังบันทึก...` และกดซ้ำไม่ได้
- ถ้า API ปฏิเสธ ทั้งชุดไม่ถูกแก้ และหน้าจอโหลดข้อมูลใหม่เพื่อไม่ให้แสดงสถานะที่ไม่ตรงฐานข้อมูล

## การเข้าถึง (accessibility)

- checkbox ทุกตัวมี `aria-label` ระบุชื่อรายการ
- modal ใช้ `role="dialog"`, `aria-modal`, `aria-labelledby`
- แจ้งเตือนใช้ `role="alert"` ข้อความสำเร็จใช้ `role="status"`
- `:focus-visible` มีขอบชัดเจนทุกตัวควบคุม
